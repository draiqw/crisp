\begin{abstract}
Обучение с учителем (SFT) и обучение с подкреплением с проверяемыми наградами (RLVR) -- зрелые подходы к дообучению больших языковых моделей. Однако оба трудно применить, если для целевой предметной области нет отобранного набора пар <<вопрос--ответ>> (QA).
Мы предлагаем сквозной конвейер генерации данных, который превращает исходные PDF-документы предметной области в два переиспользуемых артефакта: корпус для предобучения и QA-датасет, пригодный без изменений и для SFT, и для RL. Конвейер состоит из четырёх этапов. Сначала OCR преобразует PDF в структурированный Markdown с сохранением математической нотации, таблиц и иерархии документа. Затем очистка, разбиение на фрагменты, фильтрация и оценка качества с помощью LLM дают чистый корпус для предобучения. На третьем этапе самоигра на основе корпуса генерирует сложные пары <<вопрос--ответ>> вблизи границы возможностей модели, то есть примеры с откалиброванной сложностью. Наконец, полученный журнал взаимодействий фильтруется многокритериальным LLM-судьёй, и на выходе получается готовый к обучению QA-датасет.
Конвейер применяется к трём русскоязычным STEM-областям: общим дисциплинам университетского уровня, линейной алгебре, теории вероятностей и математической статистике. Эксперименты с продолженным предобучением моделей разного масштаба, как базовых, так и инструктивных, показывают, что полученный корпус сопоставим по качеству с открытыми датасетами для предобучения. Сгенерированный QA-датасет оценивается дообучением с помощью GRPO; завершённые запуски показывают результаты, конкурентоспособные с открытыми эталонными датасетами. Поскольку одни и те же примеры можно напрямую использовать и для SFT, и для RL, отдельный датасет для SFT не нужен.
Мы публикуем весь конвейер вместе с тремя датасетами, полученными в ходе экспериментов.
\end{abstract}

\textbf{Ключевые слова:} самоигра, обучение с подкреплением, большие языковые модели, курирование данных, GRPO, синтез данных на основе корпуса

\section{Введение}\label{sec:intro}

\begin{figure}[t]
  \centering
  \figmaybe{pipeline_factory.pdf}{0.8\textwidth}
  \caption{Сквозная фабрика данных: на входе PDF-документы, на выходе два датасета -- корпус для предобучения и QA-датасет для SFT/RL.}
  \label{fig:pipeline}
\end{figure}

Дообучение (post-training) больших языковых моделей (LLM) -- обучение с учителем (SFT) на отобранных демонстрациях и обучение с подкреплением с проверяемыми наградами (RLVR) с помощью GRPO~\cite{shao2024deepseekmath} и Dr.\,GRPO~\cite{liu2025drgrpo} -- хорошо отработано для узкого набора изученных областей: школьной математики, генерации кода и диалоговых ассистентов. Однако эти подходы непригодны для областей, где нет отобранного набора пар <<вопрос--ответ>> (QA) с надёжными эталонными ответами и откалиброванной сложностью. Основным узким местом стали уже не алгоритмы обучения, а получение данных, тогда как ручная разметка экспертами остаётся слишком дорогой.

У существующих автоматических подходов есть известные ограничения. Дистилляция из модели-учителя~\cite{wang2022selfinstruct,xu2023wizardlm,luo2023wizardmath} ограничена возможностями учителя и его знанием предметной области и часто неэффективна в узких доменах. Сбор сырого корпуса~\cite{penedo2024fineweb} даёт данные для предобучения, но не пары <<вопрос--ответ>>. Генерация вопросов по корпусу обычно не калибрует их сложность, а самоигра без опоры на документы~\cite{huang2025rzero,zhao2025absolute} подвержена галлюцинациям и дрейфу распределения.

Самоигра \emph{на основе корпуса}, в которой генератор вопросов работает с реальным документом, а эталонные ответы извлекаются из текста, сочетает фактическую обоснованность с адаптивной сложностью. Сложность регулируется тем, что генератор вопросов получает награду в зависимости от дисперсии успешности отвечающей модели. Эту идею предложили авторы SPICE~\cite{spice} в виде алгоритма обучения, но код и данные не опубликовали. Мы заново реализуем и расширяем этот подход: его схема награды и принцип взаимодействия двух ролей становятся основой более широкой сквозной \emph{фабрики данных}, которую мы называем \textbf{CRISP} (\textbf{C}orpus-grounded Challenger--\textbf{R}easoner Self-Play). Вместо одного обученного чекпойнта CRISP порождает два переиспользуемых артефакта: корпус для предобучения и QA-датасет, пригодный и для SFT, и для RL (рис.~\ref{fig:pipeline}).

\textbf{Вклад.} Работа содержит три результата, каждый из которых реализован в виде алгоритма и публикуется вместе со статьёй:
\begin{enumerate}
    \item \textbf{Конвейер подготовки данных для предобучения}, который принимает набор PDF-документов предметной области и строит корпус с оценками качества и тематической разметкой для продолженного предобучения (разд.~\ref{sec:method-pretrain}).
    \item \textbf{Алгоритм самоигры}, обучающий одну языковую модель в двух ролях (Challenger и Reasoner) с помощью Dr.\,GRPO и награды, зависящей от дисперсии, и формирующий журнал вопросов на границе возможностей модели (разд.~\ref{sec:method-selfplay}).
    \item \textbf{Конвейер курирования данных для выравнивания}, который превращает журнал самоигры в единый готовый к обучению QA-датасет, пригодный без изменений и для SFT, и для RL, с помощью многокритериальной фильтрации LLM-судьёй (разд.~\ref{sec:method-curation}).
\end{enumerate}

Мы проверяем конвейер целиком на трёх русскоязычных STEM-областях: общих дисциплинах университетского уровня, линейной алгебре, теории вероятностей и статистике. Эксперименты с продолженным предобучением моделей разного масштаба и стадии адаптации приведены в разд.~\ref{sec:corpus-eval}. Полученные QA-датасеты мы также оцениваем дообучением с помощью GRPO на открытых математических бенчмарках (разд.~\ref{sec:exp}).

\textbf{Структура работы.} В разделе~\ref{sec:rw} приведён обзор литературы, в разделе~\ref{sec:prelim} описаны GRPO и Dr.\,GRPO, в разделе~\ref{sec:method} -- предлагаемый конвейер, в разделе~\ref{sec:corpus-eval} -- оценка корпуса для предобучения, в разделе~\ref{sec:exp} -- эксперименты с QA-датасетами, в разделах~\ref{sec:disc}--\ref{sec:concl} -- обсуждение и заключение.

\section{Обзор литературы}\label{sec:rw}

\textbf{Дообучение LLM.}
Современные схемы дообучения обычно сочетают обучение с учителем на демонстрациях и обучение с подкреплением с проверяемыми наградами. SFT склонно переобучаться на узкое обучающее распределение и может ухудшать качество вне целевой области, тогда как RL-методы, такие как DeepSeek-R1~\cite{deepseek2025r1}, GRPO~\cite{shao2024deepseekmath} и Dr.\,GRPO~\cite{liu2025drgrpo}, сохраняют общие способности модели, поскольку обучают её против верификатора, а не подражанию единственному эталонному ответу. Однако этим методам нужны обучающие задачи с проверяемыми ответами. Построение таких датасетов в масштабе за пределами нескольких хорошо изученных областей остаётся серьёзной практической проблемой, на решение которой направлена наша работа.

\textbf{Адаптация к предметной области.}
Адаптация LLM общего назначения к специализированной области обычно включает два взаимодополняющих этапа: продолженное предобучение на текстах области и дообучение на предметных парах <<вопрос--ответ>>. FineWeb-Edu показывает, что оценка качества с помощью LLM эффективнее эвристической фильтрации при построении корпусов для предобучения~\cite{penedo2024fineweb}. Предметные QA-датасеты, напротив, обычно получают либо экспертной разметкой, либо дистилляцией из более сильных моделей~\cite{wang2022selfinstruct,xu2023wizardlm,luo2023wizardmath}. Оба способа не работают в узких областях, где экспертов мало, а подходящей модели-учителя может не существовать. Наш конвейер снимает эти зависимости: и корпус для предобучения, и QA-датасет для выравнивания строятся непосредственно из исходных PDF-документов.

\textbf{Синтетические данные и самоигра для рассуждений.}
Самоигра без опоры на документы~\cite{huang2025rzero,zhao2025absolute} позволяет модели генерировать и решать собственные задачи, естественным образом подстраивая сложность под её возможности. Без внешней опоры такие подходы подвержены накоплению галлюцинаций и дрейфу распределения. \emph{Обоснованная} самоигра устраняет это ограничение: генерация вопросов привязана к реальным документам, а эталонные ответы берутся непосредственно из исходного текста, как в SPICE~\cite{spice}. Мы рассматриваем обоснованную самоигру не как самостоятельную процедуру обучения, а как компонент более широкого конвейера генерации данных. Она располагается между этапом построения корпуса для предобучения и этапом курирования данных для выравнивания и порождает QA-датасет, который можно использовать для SFT или RL независимо от модели, на которой он был сгенерирован.

\section{Предварительные сведения}\label{sec:prelim}

Кратко опишем два RL-компонента, используемых в цикле самоигры (разд.~\ref{sec:method-selfplay}): GRPO и его вариант Dr.\,GRPO, свободный от смещения по длине.

\subsection{Групповая относительная оптимизация политики (GRPO)}

Пусть даны запрос $x$ и политика $\pi_\theta$ с параметрами $\theta$. GRPO~\cite{shao2024deepseekmath} сэмплирует для запроса \emph{группу} из $K$ независимых ответов $\{y_i\}_{i=1}^{K}$, назначает каждому награду верификатора $r_i = R(x, y_i)$ и использует среднее по группе как базовую линию:
\begin{equation}
  A_i \;=\; \frac{r_i - \bar r}{\sigma_r},
  \qquad \bar r \,=\, \tfrac{1}{K}\!\sum_j r_j .
\end{equation}
Каждый токен $y_i$ получает преимущество $A_i$ всей последовательности. Обновление выполняется по усечённой суррогатной функции PPO с потокенным отношением правдоподобий $\rho_{i,t} = \exp\!\bigl(\log\pi_{\theta_{\text{new}}}(y_{i,t}|x,y_{i,<t}) - \log\pi_{\theta_{\text{old}}}(\cdot)\bigr)$ и порогом усечения $\epsilon$:
\begin{equation}
  \mathcal{L}_{\text{GRPO}} \,=\, -\sum_{i,t}
    \frac{1}{L_i}\min\!\bigl(\rho_{i,t} A_i,
      \mathrm{clip}(\rho_{i,t}, 1\!\pm\!\epsilon)\,A_i\bigr),
  \label{eq:GRPO}
\end{equation}
где $L_i$ -- длина ответа $y_i$.

\subsection{Dr.\,GRPO}

Dr.\,GRPO~\cite{liu2025drgrpo} устраняет два недостатка GRPO. Во-первых, замена длины ответа $L_i$ фиксированной максимальной длиной $L_{\max}$ убирает смещение по длине, вызванное нормировкой на каждую последовательность. Во-вторых, метод отказывается от нормировки на стандартное отклонение, которая может раздувать обновления для запросов с почти нулевой дисперсией награды, и использует центрированные награды напрямую. Итоговая функция потерь:
\begin{equation}
  \mathcal{L}_{\text{Dr.GRPO}} \,=\, -\frac{1}{L_{\max}}\!\sum_{i,t}
    \min\!\bigl(\rho_{i,t}\,\tilde A_i,
      \mathrm{clip}(\rho_{i,t}, 1\!\pm\!\epsilon)\,\tilde A_i\bigr),
  \label{eq:drgrpo}
\end{equation}
где $\tilde A_i = r_i - \bar r$. Мы используем~\eqref{eq:drgrpo} без изменений при обновлении и Challenger, и Reasoner (разд.~\ref{sec:method-selfplay}).

\section{Метод}\label{sec:method}

Предлагаемый конвейер превращает набор PDF-документов в два артефакта: корпус для предобучения и QA-датасет, пригодный и для SFT, и для RL (рис.~\ref{fig:pipeline}). Метод состоит из двух частей. \textbf{(A)~Генерация данных для предобучения} (разд.~\ref{sec:method-pretrain}) включает OCR, очистку корпуса, разбиение на фрагменты и оценку качества. \textbf{(B)~Генерация данных для выравнивания} (разд.~\ref{sec:method-selfplay}, \ref{sec:method-curation}) состоит из цикла обучения самоигрой на основе корпуса и последующего курирования LLM-судьёй, на выходе которого получается готовый к обучению QA-датасет.

Все текстовые вызовы LLM выполняются моделью \textbf{Qwen3-14B} (Base или Instruct). На этапе OCR используется VLM, так как вход представлен изображениями.

\subsection{Генерация данных для предобучения}\label{sec:method-pretrain}

\textbf{Этап~1: OCR.}\label{sec:corpus-ocr}
PDF-документы преобразуются в Markdown с помощью \textbf{Chandra}~\cite{chandra} -- открытой модели на основе Qwen3-VL, дообученной компанией Datalab для конвертации PDF в Markdown. Среди рассмотренных OCR-систем Chandra надёжнее всех сохраняет математические выражения, структуру таблиц и иерархию документа (прил.~\ref{app:ocr}). Хотя полученный Markdown высокого качества, в нём остаются артефакты OCR, библиотечные пометки и издательские метаданные, что требует последующей очистки. Типы шума описаны в прил.~\ref{app:noise}.

\textbf{Этап~2: очистка, разбиение на фрагменты, фильтрация.}\label{sec:corpus-filter}
Извлечённый Markdown превращается в корпус JSONL с оценками качества и тематической разметкой в три шага: (i)~удаление артефактов OCR и издательских метаданных регулярными выражениями, (ii)~разбиение на смысловые фрагменты (чанки) иерархическим поиском границ, (iii)~оценка качества и тематическая разметка с помощью LLM. Абляция в разд.~\ref{sec:corpus-eval-deltappl} проверяет, помогает ли эта фильтрация на последующих этапах.

Оценка качества следует рубрике FineWeb-Edu~\cite{penedo2024fineweb}, фрагменты низкого качества отбрасываются. Детали реализации, правила фильтрации и гиперпараметры приведены в прил.~\ref{app:clean}. Полученный корпус служит одновременно датасетом для продолженного предобучения (разд.~\ref{sec:corpus-eval}) и входом для этапа самоигры, описанного ниже.

\subsection{Генерация данных для выравнивания: самоигра}\label{sec:method-selfplay}

Одна и та же базовая модель работает в двух ролях: \textbf{Challenger} читает фрагменты документов из этапа~2 и формулирует вопросы, а \textbf{Reasoner} отвечает на них без доступа к документу (closed-book). Обе роли обучаются совместно с помощью Dr.\,GRPO (ур.~\eqref{eq:drgrpo}) с отдельными LoRA-адаптерами ($\theta_C$, $\theta_R$) поверх общей замороженной модели $\pi_\theta$.

\textbf{Роли.} По фрагменту с тематическими метками Challenger выдаёт задачу в формате JSON: либо с выбором ответа (один верный вариант и три альтернативы), либо со свободным ответом одного из типов $\{$целое, вещественное, выражение, строка$\}$. Промпт требует, чтобы эталонный ответ опирался на текст фрагмента, поэтому фактическая корректность сводится к верности известному источнику. Простой парсер отбрасывает некорректные записи. Reasoner видит только задачу и сэмплирует $K$ ответов. Корректность $i$-го ответа $\ell_i \in \{0, 1\}$ проверяется точным совпадением для задач с выбором ответа или с помощью Math-Verify~\cite{mathverify} для математических задач со свободным ответом.

\textbf{Награда.} Пусть $\bar\ell = \tfrac{1}{K}\!\sum_i \ell_i$, а дисперсия корректности для вопроса $v = \bar\ell\,(1-\bar\ell)$. Награда Challenger
\begin{equation}
  r_C(q, a^\star) \;=\; \exp\!\Bigl(-\frac{(v - 0.25)^2}{2 \cdot 0.01}\Bigr)
  \label{eq:variance-reward}
\end{equation}
имеет гауссову форму по $v$ с максимумом при $\bar\ell = 0.5$. Награда за дисперсию, а не за долю верных ответов, удерживает генерируемые вопросы \emph{на грани решаемости} для текущего Reasoner: по мере его улучшения граница, максимизирующая дисперсию, смещается вверх, и Challenger следует за ней. Таким образом, учебная программа порождается вместе с обучением, а не задаётся заранее. Некорректные записи Challenger получают фиксированный штраф $r_C = -0.1$, который используется только для центрирования базовой линии; такие записи отфильтровываются до вычисления градиента. Награда Reasoner -- бинарная корректность $r^R_i = \ell_i$.

\textbf{Алгоритм обучения.} На каждом \emph{внешнем шаге} сэмплируется батч из $B$ фрагментов и выполняется шестифазный цикл алгоритма~\ref{alg:selfplay}.

\begin{algorithm}[t]
\caption{Самоигра на основе корпуса (один внешний шаг).}
\label{alg:selfplay}
\begin{algorithmic}[1]
\Require корпус $\mathcal{D}$ фрагментов с оценками качества; базовая модель $\pi_\theta$; адаптеры $\theta_C, \theta_R$; батч $B$; размер группы $K$; число эпох PPO $H$; порог усечения $\epsilon$
\State $\mathcal{B} \gets$ сэмплировать $B$ фрагментов из $\mathcal{D}$
\Statex \textbf{Фаза 1 (генерация Challenger).}
\For{каждого фрагмента $d \in \mathcal{B}$}
  \State $(q_d, a^\star_d, \text{type}_d) \gets \pi_{\theta + \theta_C}(d)$
  \State $\text{valid}_d \gets \text{\textsc{ParseValidate}}(q_d, a^\star_d, \text{type}_d)$
\EndFor
\State $\mathcal{V} \gets \{ d \in \mathcal{B} : \text{valid}_d \}$
\Statex \textbf{Фаза 2 (генерация Reasoner).}
\For{каждого $d \in \mathcal{V}$}
  \State $\{a_{d,i}\}_{i=1}^{K} \gets$ $K$ сэмплов из $\pi_{\theta + \theta_R}(q_d, \text{type}_d)$
  \State $\ell_{d,i} \gets \text{\textsc{Verify}}(a_{d,i}, a^\star_d, \text{type}_d)$
\EndFor
\Statex \textbf{Фаза 3 (награды и преимущества, Dr.\,GRPO).}
\For{каждого $d \in \mathcal{B}$}
  \If{$d \in \mathcal{V}$}
    \State $v_d \gets \tfrac{1}{K}\!\sum_i\!(\ell_{d,i} - \bar\ell_d)^2$
    \State $r^C_d \gets \exp(-(v_d - 0.25)^2 / 0.02)$
  \Else
    \State $r^C_d \gets -0.1$ \Comment{штраф, только для базовой линии}
  \EndIf
\EndFor
\State $\bar r^C \gets \tfrac{1}{B}\sum_d r^C_d$;\,\, $A^C_d \gets r^C_d - \bar r^C$
\For{каждого $d \in \mathcal{V}$, $i \in [K]$}
  \State $r^R_{d,i} \gets \ell_{d,i}$;\,
        $\bar r^R_d \gets \tfrac{1}{K}\sum_j r^R_{d,j}$
  \State $A^R_{d,i} \gets r^R_{d,i} - \bar r^R_d$
\EndFor
\Statex \textbf{Фаза 4 (обновление $\theta_R$ по GRPO).}
\State Заморозить $\theta_C$; для $h = 1\!:\!H$ выполнить шаг Dr.\,GRPO на
\Statex \quad $\{(q_d, a_{d,i}, A^R_{d,i})\}$ с порогом $\epsilon$
\Statex \textbf{Фаза 5 (обновление $\theta_C$ по GRPO).}
\State Заморозить $\theta_R$; для $h = 1\!:\!H$ выполнить шаг Dr.\,GRPO на
\Statex \quad $\{(d, q_d, A^C_d) : d \in \mathcal{V}\}$ с порогом $\epsilon$
\Statex \textbf{Фаза 6 (синхронизация).}
\State Передать обновлённые $\theta_C, \theta_R$ инференс-воркерам
\Statex \quad через встроенный API замены LoRA в vLLM.
\State \textbf{Записать} каждую $(d, q_d, a^\star_d, \{a_{d,i}, \ell_{d,i}\}, r^C_d, \text{шаг})$
\Statex \quad в журнал вопросов, используемый на этапе~4.
\end{algorithmic}
\end{algorithm}

Фазы~4 и~5 применяют Dr.\,GRPO (ур.~\eqref{eq:drgrpo}) к одной роли, пока адаптер другой роли заморожен. Фаза~6 синхронизирует обновлённые адаптеры с инференс-воркерами через встроенную замену LoRA в vLLM. Инженерные детали приведены в прил.~\ref{app:selfplay}.

\subsection{Генерация данных для выравнивания: курирование}\label{sec:method-curation}

После окончания самоигры сырой журнал вопросов, в котором вопросы на границе возможностей перемешаны с некорректными, нерелевантными, тривиальными и имеющими неверный эталонный ответ, превращается в единый готовый к обучению QA-датасет с помощью фиксированной процедуры. Пусть $\pi^\star$ -- самостоятельная политика, полученная слиянием лучшего чекпойнта Reasoner с весами базовой модели (разд.~\ref{sec:exp-questions}).

\textbf{Процедура.}
\textbf{(i) Переоценка.} На каждый вопрос из журнала одна фиксированная политика $\pi^\star$ отвечает $K$ раз. Это заменяет нестационарную долю верных ответов, записанную во время обучения (вопросы с разных шагов оценивались разными версиями Reasoner), единой согласованной меткой сложности относительно модели.
\textbf{(ii) Фильтр по сложности.} Оставляются вопросы, которые $\pi^\star$ решает менее чем в половине попыток (доля верных ответов $<0.5$), -- всё ещё сложные, но обучаемые примеры на границе её возможностей.
\textbf{(iii) Корректность и обоснованность.} Оставляются записи, прошедшие валидатор на этапе генерации, и восстанавливается полный исходный фрагмент (в журнале он хранится усечённым), чтобы судья видел документ, по которому был составлен вопрос.
\textbf{(iv) Судья.} LLM-судья оценивает каждый оставшийся вопрос по $10$ критериям: семь бинарных ($\{0,1\}$) -- самодостаточность, соответствие теме, корректность формулировки, корректность ответа, обоснованность текстом, отсутствие утечки ответа, фактическая верность -- и три градуированных ($\{0,\dots,5\}$) -- сложность, качество дистракторов, ясность. Оценки выдаются в виде \verb|\boxed{x:n}| и разбираются нестрогим парсером (прил.~\ref{app:judge}).
\textbf{(v) Отбор.} Вопрос попадает в датасет тогда и только тогда, когда все семь бинарных критериев равны $1$; три градуированные оценки сохраняются как столбцы, чтобы в дальнейших абляциях можно было стратифицировать по сложности, качеству дистракторов или ясности.

\textbf{Судья -- отдельная, более сильная модель, а не сама политика.}
Заманчиво позволить политике оценивать собственные вопросы: не нужна дополнительная модель, и можно переиспользовать чекпойнт генерации. Мы проверили этот вариант и считаем его небезопасным: политика -- снисходительный судья своих же ответов. В роли собственного судьи политика на $14$B пропускает через бинарный фильтр $70$--$87\%$ вопросов и признаёт ответ корректным почти всегда ($89\%$/$77\%$ для пулов base/instruct). Отдельный, более сильный судья (Qwen3.5-27B) пропускает лишь $12$--$47\%$ и подтверждает гораздо меньше эталонных ответов (вплоть до $14\%$), отбраковывая множество некорректных или ошибочных примеров, которые пропускает самосудья. Поскольку неверный эталонный ответ губителен для \emph{обоих} сценариев -- ложный сигнал верификатора для RL и неверная демонстрация для SFT, -- для итогового датасета мы используем отдельного судью, а самосудью оставляем только как абляцию (прил.~\ref{app:judge}).

\textbf{Результат.}
Процедура даёт один \textbf{QA-датасет}: по строке JSONL на каждый прошедший вопрос с промптом, проверяемым эталонным ответом, исходным фрагментом, тремя градуированными оценками судьи и успешным ответом $\pi^\star$. Одни и те же строки без изменений используются в обоих сценариях: RL берёт эталонный ответ как сигнал верификатора, SFT -- ответ $\pi^\star$ как целевую демонстрацию.

\textbf{Калибровка сложности.}
Чтобы оценить сложность сгенерированных вопросов, мы калибруем оценки сложности этапа~4 по нескольким открытым математическим бенчмаркам. По полученной шкале большинство сгенерированных вопросов попадает в диапазон сложности DAPO/DeepMath, а не GSM8K, что согласуется с целью награды за дисперсию.

\section{Оценка корпуса}\label{sec:corpus-eval}

Ценность корпуса для предобучения определяется приростом качества, который он даёт, но любая отдельная метрика -- статистики текста, перплексия, кластеризация эмбеддингов, обучаемость при дообучении -- сама по себе в лучшем случае лишь коррелирует с ним. Поэтому мы оцениваем результат этапа~2 по \emph{двум независимым осям} на трёх моделях (GPT-2~124M, Qwen3-14B-Base, Qwen3-14B-Instruct):

\begin{itemize}
  \item \textbf{Функциональная проба} (разд.~\ref{sec:corpus-eval-deltappl}): на каждом корпусе проводится продолженное предобучение с фиксированным бюджетом, и относительное снижение перплексии на отложенной выборке $\Delta\mathrm{PPL}\% = 100\,(1 - \mathrm{PPL}_{\text{final}}/\mathrm{PPL}_{\text{init}})$ принимается за количество обучаемого сигнала в корпусе.
  \item \textbf{Статическая проба} (разд.~\ref{sec:corpus-eval-static}): перплексия на фиксированной тестовой части без обучения и четыре статистики, не зависящие от модели, -- повторяемость $n$-грамм и лексическое разнообразие, семантическое разнообразие эмбеддингов, пересечение $5$-грамм по Жаккару с каждым эталонным корпусом и распределение перплексии по документам (среднее, медиана, тяжёлый хвост).
\end{itemize}

Пробы дополняют друг друга: $\Delta\mathrm{PPL}\%$ показывает, \emph{сколько модель может извлечь} из корпуса при одинаковом обучении, а перплексия и статические статистики -- \emph{как выглядит корпус} до какого-либо обучения. Нам нужен корпус, хороший по обеим осям.

\textbf{Сравниваемые датасеты.}
Мы сравниваем три корпуса, полученных нашим конвейером, с семью открытыми эталонами:
\begin{itemize}
  \item \textbf{Наши}: \textbf{STEM\_corpus} (общие дисциплины университетского уровня по информатике и математике, основной результат полного конвейера), \textbf{linalg\_corpus} (линейная алгебра и ОДУ), \textbf{stat\_corpus} (теория вероятностей и математическая статистика). Оба предметных корпуса получены теми же этапами~1--2 без подбора параметров.
  \item \textbf{Веб-корпуса для предобучения}: FineWeb-Edu, OpenWebMath, mC4-ru.
  \item \textbf{QA и рассуждения}: NaturalReasoning (вопрос и эталонный ответ конкатенируются для CLM-лосса).
  \item \textbf{Математические датасеты для SFT/RL}: GSM8K, DAPO-Math, DeepMath.
\end{itemize}

\subsection{Статическая проба: статистики текста}\label{sec:corpus-eval-static}

\textbf{Лексическое разнообразие.}
Фильтр этапа~2 вдвое снижает повторяемость $5$-грамм (STEM\_corpus\_v0 $0.333 \to$ STEM\_corpus\_v1 $0.169$): шаблонный текст удаляется без ущерба для содержательного. Полные лексические статистики приведены в прил.~\ref{app:corpus-eval}.

\textbf{Пересечение $5$-грамм по Жаккару с эталонами.}
Для всех пар корпусов из разных источников значение ниже $5\!\times\!10^{-3}$; максимальные значения -- STEM\_corpus\_v1 и DeepMath ($4.0\!\times\!10^{-3}$), STEM\_corpus\_v1 и NaturalReasoning ($1.7$--$2.5\!\times\!10^{-3}$). У linalg и stat пересечение со STEM\_corpus\_v1 равно $0.065$/$0.072$ (отношение подмножества), а с каждым открытым эталоном -- ниже $4\!\times\!10^{-3}$. Следовательно, утечка тестовых данных не является проблемой.

\textbf{Вывод.}
Обе пробы согласуются: STEM\_corpus\_v1 занимает нишу математического предобучения между математическими SFT-датасетами (DeepMath и DAPO, PPL $2.5$--$2.4$) и OpenWebMath ($3.55$), а плотность обучаемого сигнала позволяет $22$\,M наших токенов сравняться по $\Delta$PPL со $186$\,M токенов OpenWebMath. Предметные корпуса linalg и stat идут ещё дальше: при ещё более низкой исходной перплексии они дают двузначное снижение $\Delta$PPL на Instruct всего на $1.6$--$2.2$\,M токенов. Статические статистики исключают утечку тестовых данных, а распределение перплексии по документам показывает, что фильтр этапа~2 удаляет катастрофически плохие фрагменты, не выравнивая основную массу корпуса. Это необходимое условие того, чтобы тот же корпус годился как вход для самоигры на этапе~3.

\section{Эксперименты}\label{sec:exp}

Результат фабрики -- \emph{датасет}, а не чекпойнт, поэтому мы оцениваем его так же, как любой обучающий набор: дообучаем фиксированную политику и проверяем, становится ли она лучше той же политики, дообученной по идентичному рецепту на сильнейшем открытом датасете для данной области. В качестве рецепта оценки мы используем GRPO, поскольку он даёт более сильный внешний сигнал -- проверяемую награду, -- а отобранные строки без изменений подходят и для SFT (разд.~\ref{sec:method-curation}); поэтому результат для RL переносится на SFT без отдельного датасета. Каждый запуск стартует с объединённой политики $\pi^\star$ (разд.~\ref{sec:method-curation}), использует общий рецепт GRPO из прил.~\ref{app:downstream-grpo} и отличается только обучающим набором.

\subsection{Три вопроса проектирования}\label{sec:exp-questions}

Чтобы превратить журнал самоигры в обучающий набор, нужно сделать три выбора, которые цикл самоигры сам по себе не определяет. Мы формулируем каждый как вопрос и фиксируем ответ один раз; к Q1 мы возвращаемся как к абляции в разд.~\ref{sec:exp-results}, а упомянутые ниже механизмы подробно описаны в разд.~\ref{sec:method-curation}.

\textbf{Q1: важно ли обучать Reasoner?}
Самоигра обновляет обе роли, поэтому Challenger преследует \emph{движущуюся} границу по мере улучшения Reasoner, а награда за дисперсию поощряет вопросы на этой смещающейся границе. Естественная абляция -- проверить, нужно ли Reasoner вообще обучаться: мы замораживаем Reasoner в исходных весах (он по-прежнему отвечает $K$ раз, давая сигнал дисперсии, но его адаптер не обновляется), так что Challenger нацеливается на \emph{фиксированную} границу базовой модели с той же наградой. Этот вариант мы называем \textbf{Challenger-only}, курируем датасет из его журнала той же процедурой (Q2--Q3) и проводим сравнение на области \emph{линейной алгебры}.

\textbf{Q2: какой чекпойнт использовать?}
Во время самоигры Reasoner хранится как \emph{отдельный LoRA-адаптер} поверх замороженной базовой модели (разд.~\ref{sec:method-selfplay}). На узких корпусах цикл переобучается в зависимости от числа \emph{эпох} по небольшому набору фрагментов: точность Reasoner на отложенной выборке достигает пика и затем снижается (прил.~\ref{app:dynamics}). Поэтому мы отбрасываем последний чекпойнт и берём \textbf{лучший адаптер Reasoner по отложенной выборке}. Затем этот адаптер \emph{сливается} с весами базовой модели, и двухролевая модель превращается в одну самостоятельную политику Reasoner $\pi^\star$, отвечающую на любой запрос без адаптера. Она используется и как модель для последующего дообучения, и как модель для переоценки в Q3.

\textbf{Q3: какие вопросы попадают в датасет?}
Доли верных ответов, записанные во время самоигры, нестационарны: вопросы, сгенерированные в начале обучения, оценивались более слабым Reasoner, чем поздние. Чтобы получить согласованную оценку сложности, итоговая политика $\pi^\star$ заново отвечает на каждый вопрос из журнала $K$ раз. Мы оставляем только вопросы, решённые не более чем в половине попыток (доля верных ответов $\le 0.5$), -- фильтр сложности относительно модели, не зависящий от момента генерации вопроса. Оставшиеся вопросы проходят LLM-судью из разд.~\ref{sec:method-curation} и только затем попадают в итоговый QA-датасет.

\subsection{Постановка эксперимента}\label{sec:exp-setup}

\textbf{Сгенерированные датасеты.}
Фабрика выдаёт по одному QA-датасету на каждую область: \textbf{STEM-вопросы} (общий корпус), \textbf{вопросы по линейной алгебре} (linalg) и \textbf{вопросы по статистике} (stat). Каждая строка содержит проверяемый эталонный ответ и успешный ответ $\pi^\star$ -- сигнал верификатора для RL и демонстрацию для SFT.

\textbf{Открытые эталонные датасеты.}
Каждый сгенерированный датасет сравнивается с сильнейшим открытым обучающим набором для своей области при одинаковом рецепте. \emph{Общая математика:} текстовые задачи школьного уровня GSM8K~\cite{cobbe2021gsm8k} и олимпиадные DAPO-Math-17k и DeepMath-103K. \emph{Линейная алгебра:} \textbf{LinAlg-Bench}~\cite{agarwal2026linalgbench} -- $660$ задач девяти типов операций (определитель, собственные значения, ранг, размерность ядра, след, транспонирование, умножение матриц, произведение матрицы на вектор, степень матрицы), каждая в LaTeX с эталонным ответом, проверяемым SymPy, и типизированным верификатором для каждого типа. \emph{Статистика:} \textbf{math\_cp} -- раздел Counting \& Probability датасета MATH~\cite{hendrycks2021math} ($474$ олимпиадные задачи, уровни сложности $1$--$5$). Оба узких набора существуют в исходной английской версии и в русском переводе (LinAlgBench-EN/RU, math\_cp-EN/RU), что позволяет контролировать несовпадение языков обучения и оценки.

\textbf{Бенчмарки для оценки.}
Каждый чекпойнт оценивается на фиксированном наборе из $21$ бенчмарка по единому протоколу декодирования (avg@$3$, $T=0.6$); бенчмарки разбиты на три предметные группы и внедоменный набор. \emph{Общая группа} (13): GSM8K и MATH-500 на английском и русском, AIME-24/25, MatharenaApex (и его shortlist), MMLU-STEM, RuMMLU-STEM, GPQA-Diamond, UGMath-general и отложенные части DAPO/DeepMath. \emph{Линейная алгебра} (3): LinAlgBench-EN/RU и UGMath-linalg. \emph{Статистика} (3): math\_cp-EN/RU, UGMath-prob/stat, а также StatEval с оценкой LLM-судьёй (приводится, но не входит в средние по группе). Русские версии и разделы UGMath -- независимые отложенные бенчмарки, а не обучающие распределения. В табл.~\ref{tab:eval-broad}--\ref{tab:eval-narrow} приведено репрезентативное подмножество каждой группы; полные результаты по всем чекпойнтам и всем $21$ бенчмаркам вместе со средним по общей группе публикуются вместе с кодом.

\textbf{Рецепт, чекпойнт, метрика.}
Каждый запуск -- GRPO с дообучением всех параметров, стартующий с $\pi^\star$, с проверяемой наградой за формат и корректность (прил.~\ref{app:downstream-grpo}); чекпойнты сохраняются каждые $100$ шагов. Согласно правилу Q2, для каждого запуска приводится чекпойнт с максимальной средней точностью по его \emph{предметной} группе. Это избавляет узкий запуск от размывания средним по $20$ бенчмаркам и является единственным гиперпараметром запуска, выбранным по отложенным данным. В каждой ячейке приводятся две точности при $T=0.6$ и $K=3$ сэмплах: acc@$1$ (avg@$3$, средняя точность одного сэмпла) и acc@$k$ (pass@$3$, доля задач, решённых хотя бы одним из $3$ сэмплов); выбор чекпойнта (Q2) делается по acc@$1$. Выбранный шаг указан в каждой строке, лучший по acc@$1$ результат в столбце среди завершённых (не \tbd) строк выделен \textbf{жирным}.

\subsection{Результаты}\label{sec:exp-results}

\textbf{Общий корпус (табл.~\ref{tab:eval-broad}).}
На Qwen3-14B-Base каждый открытый математический набор резко улучшает свой целевой бенчмарк -- GSM8K $82.2\!\to\!95.3$, MATH-500 до $82.2$ при DeepMath, -- а DAPO-Math дополнительно переносится на GPQA-Diamond ($28.8\!\to\!40.9$), MMLU-STEM ($79.2\!\to\!87.9$) и RuMMLU ($77.1\!\to\!84.5$), поднимая среднее по общей группе с $51.0$ до $57.7$; таким образом, базовые линии на Base сильные, а не слабые. Русские и английские версии меняются согласованно (MATH-500\textsubscript{ru} следует за MATH-500), то есть прирост не зависит от языка. На Qwen3-14B-Instruct, уже близкой к потолку, те же олимпиадные наборы, напротив, \emph{ухудшают} модель: DAPO и DeepMath снижают AIME-24 с $56.7$ до $30.0$/$33.3$ и MATH-500 с $91.4$ до $84.8$/$87.8$ (среднее по группе $67.2\!\to\!60.0$/$62.2$), достигая пика на шаге~$100$ и затем падая, а GSM8K -- единственный открытый набор, помогающий Instruct (AIME-24 $56.7\!\to\!66.7$, среднее $67.2\!\to\!68.4$). Это та планка, которую должны преодолеть наши STEM-вопросы.

\textbf{Узкие области (табл.~\ref{tab:eval-narrow}).}
На политике Base каждый открытый предметный набор улучшает свой бенчмарк (LinAlgBench $42.4\!\to\!52.4$, math\_cp $71.9\!\to\!93.2$), вариант на том же языке выигрывает на оценке на этом языке (LinAlgBench-RU лучший на LinAlgBench-RU с $52.9$; math\_cp-RU лучший на math\_cp-RU с $92.0$), а запуски на math\_cp переносятся и на MATH-500 ($73.8\!\to\!85.4$), и на StatEval ($69.7\!\to\!75.7$); набор LinAlgBench из $660$ примеров сдвигает MATH-500 лишь умеренно. На близкой к потолку политике Instruct открытые узкие наборы, напротив, \emph{ухудшают} почти все бенчмарки (LinAlgBench $61.7\!\to\!47.1$, math\_cp $94.9\!\to\!94.1$), и среди открытых эталонов базовая линия остаётся лучшей в $7$ из $8$ столбцов. Это ещё одно свидетельство того, что открытые эталоны -- слабый обучающий сигнал для уже сильной модели и невысокая планка для наших сгенерированных данных. Сложные части UGMath-linalg/prob-stat почти не меняются ни при каком источнике. Наши вопросы linalg и stat добавляются в каждую группу третьим источником для обеих политик.

\textbf{Сгенерированные датасеты и абляция Q1.}
Результаты дообучения повторяют картину, наблюдаемую для открытых эталонов: Base улучшается, Instruct насыщена. На политике \textbf{Base} наш STEM-датасет широко улучшает $\pi^\star$ (GSM8K $82.2\!\to\!95.2$, MATH-500 $73.8\!\to\!80.8$), конкурентоспособен с сильнейшим открытым набором по каждому столбцу и даёт лучший результат в столбцах GSM8K\textsubscript{ru} ($93.9$) и AIME-25 ($16.7$); датасеты linalg и stat улучшают свои группы относительно $\pi^\star$ (LinAlg\textsubscript{en} $42.4\!\to\!45.9$, math\_cp\textsubscript{ru} $70.3\!\to\!76.8$), но пока не догоняют открытый набор на том же языке. На политике \textbf{Instruct}, уже близкой к потолку в этих областях, общий STEM-набор \emph{ухудшает} модель -- признак переобучения политики, которой почти нечему учиться в домене; именно поэтому наш конвейер ориентирован на политику Base. Что касается \emph{Q1}, на Base полный датасет самоигры linalg превосходит абляцию Challenger-only в предметных столбцах LinAlgBench (LinAlg\textsubscript{en} $45.9$ против $42.6$, LinAlg\textsubscript{ru} $45.0$ против $44.3$): обучение Reasoner, а не только Challenger, повышает качество вопросов. Единственные ещё не заполненные значения (\tbd) -- столбец StatEval для сгенерированных датасетов.

\section{Этап 3: конфигурация самоигры}\label{app:selfplay}

\subsection{Гиперпараметры (основной запуск)}
Внешний батч $B = 64$ фрагмента; размер группы Reasoner $K = 8$; внутренних эпох PPO $H = 2$; порог усечения $\epsilon = 0.2$; скорость обучения $10^{-6}$ с постоянным расписанием; ранг/alpha LoRA $128/128$ на основной модели $14$\,B; размер градиентного подбатча $4$ с микробатчами, отсортированными по длине; сэмплирование в vLLM с $T = 0.6$, $\mathrm{top\!-\!p} = 0.95$, $\mathrm{top\!-\!k} = 20$, без presence penalty; максимальная длина ответа политики $2{,}048$ токенов, она же глобальная нормировочная константа лосса Dr.\,GRPO.

\subsection{Конфигурация кластера}
$8$ GPU A100--$80$\,GB в одном узле. Тренер занимает GPU $0$--$4$ (FSDP с \texttt{ShardingStrategy.FULL\_SHARD}, автоматическое оборачивание трансформерных блоков, \texttt{MixedPrecision(param=bf16, reduce=fp32)}). Инференс-воркеры vLLM занимают GPU $5$--$7$, каждый с \texttt{tensor\_parallel\_size = 1}, и разделяют базовую модель через mmap в памяти хоста.

\subsection{Промпты}
Промпт Challenger требует от модели JSON-объект с полями \texttt{task\_type}, \texttt{answer\_type}, \texttt{question}, \texttt{answer} и необязательным \texttt{options}, опирающийся на фрагмент и список тем. Промпт Reasoner задаёт тип ответа и (для задач с выбором) варианты и требует дать итоговый ответ внутри \verb|\boxed{...}|. Оба промпта публикуются вместе с кодом.

\subsection{Встроенный API замены LoRA}
Мы используем три вызова, доступные в vLLM~0.17 на работающем движке: \texttt{add\_lora(path, lora\_id)}, \texttt{pin\_lora(lora\_id)}, \texttt{remove\_lora(lora\_id)}. Тренер сохраняет два LoRA-адаптера на диск; инференс-воркеры открепляют старый идентификатор адаптера, загружают новый с диска и закрепляют его. Перезапуск движка не требуется.

\section{Этап 4: конфигурация судьи}\label{app:judge}

\subsection{Модель судьи и декодирование}
Итоговый датасет оценивается \emph{отдельной}, более сильной моделью -- Qwen3.5-27B в режиме рассуждений, -- а не политикой, по причинам, изложенным в разд.~\ref{sec:method-curation}. Оценка выполняется офлайн по журналу вопросов с непрерывным батчингом vLLM ($\mathrm{TP}=2$, четыре реплики с параллелизмом по данным на $8\times$A100); чат-шаблон, температура $0.6$, top-$p$ $0.95$, top-$k$ $20$, до $16$K генерируемых токенов. В качестве абляции мы также оцениваем вопросы самой политикой (Qwen3-14B-Base через шаблон продолжения, Qwen3-14B-Instruct через чат-шаблон).

\subsection{Промпт с рубрикой и парсер}
Промпт начинается с рубрики из десяти критериев, каждый описан не более чем $30$ словами и снабжён допустимым диапазоном ($\{0, 1\}$ для бинарных, $[0, 5]$ для градуированных); затем следует одна фраза с указанием оценивать каждый критерий отдельно и спецификация формата, требующая в конце ответа по одному токену \verb|\boxed{x:n}| на критерий. Парсер использует нестрогое регулярное выражение \verb|\\boxed\{\s*([a-j])\s*:\s*(\d+)\s*\}| и проверяет каждую найденную пару на попадание в диапазон критерия. При нескольких допустимых совпадениях для одного критерия берётся последнее. Значения вне диапазона отбрасываются; вопросы с пропущенным критерием помечаются и переоцениваются при следующем проходе.

\subsection{Доля прохождения по критериям и абляция самосудьи}
С отдельным судьёй бинарный фильтр (все семь критериев $=1$) пропускает $12$--$47\%$ вопросов в разных конфигурациях; ограничивающими критериями являются корректность формулировки и корректность ответа, тогда как соответствие теме, отсутствие утечки и самодостаточность выполняются для $\ge 85\%$ вопросов. Самосудья гораздо снисходительнее: он пропускает $70$--$87\%$, признавая корректность формулировки и ответа для $\approx 90$--$100\%$ собственных вопросов; например, на пуле base он принимает эталонный ответ для $89\%$ вопросов против $14\%$ у отдельного судьи. Этот разрыв -- эмпирическое обоснование использования отдельного судьи в основном конвейере. Три градуированные оценки (сложность примерно равномерно распределена по $\{1,2,3\}$, качество дистракторов сосредоточено в $\{3,4\}$, ясность -- в $\{4,5\}$) сохраняются как столбцы датасета и для фильтрации не используются.

\section{Конфигурация дообучения GRPO}\label{app:downstream-grpo}

Все сравнительные запуски из разд.~\ref{sec:exp-results} используют один и тот же рецепт GRPO с одной политикой и отличаются только обучающим набором; это стандартная настройка, отличная от двухадаптерного цикла самоигры из прил.~\ref{app:selfplay}.

\subsection{Фреймворк и политика}
Мы используем \texttt{verl}~\cite{sheng2024verl} (коммит \texttt{592cb07}) с бэкендом FSDP (\texttt{FULL\_SHARD}, автоматическое оборачивание трансформерных блоков, \texttt{MixedPrecision(param=bf16, reduce=fp32)}, gradient checkpointing) и асинхронным движком генерации vLLM на одном узле $8\!\times\!$A100-$80$\,GB. Политика -- Qwen3-14B Base или Instruct; актор обучается по всем параметрам (без LoRA и без критика -- GRPO использует групповую базовую линию).

\subsection{Проверяемая награда}
Каждый ответ оценивается по шкале $[0, 2]$, $R = R_{\text{format}} + R_{\text{correct}}$:
\begin{itemize}
  \item \emph{Формат} $R_{\text{format}}\in\{0,\,0.25,\,0.5,\,1\}$: полная награда $1$, если ответ точно соответствует шаблону \verb|<think>...</think><answer>...</answer>|; иначе по $0.25$ за каждую выполненную половину (начинается с \verb|<think>| / заканчивается \verb|</answer>|).
  \item \emph{Корректность} $R_{\text{correct}}\in\{0,1\}$: $1$, если извлечённый \verb|<answer>| совпадает с эталонным ответом. Числовые и свободные ответы проверяются нормализованным сравнением строк/дробей \emph{или} символьным равенством Math-Verify~\cite{mathverify}; на типизированных датасетах в стиле SPICE маршрутизатор по \texttt{answer\_type} дополнительно обрабатывает задачи с выбором ответа (совпадение буквы с учётом кириллицы) и ответы типов \{целое, вещественное, выражение, строка\}.
\end{itemize}
GRPO сэмплирует $K$ ответов на запрос и центрирует каждую награду средним по группе ($A_i = (r_i - \bar r)/\sigma_r$); преимущество используется в усечённой суррогатной функции PPO из ур.~\eqref{eq:GRPO} (порог $\epsilon = 0.2$).

\section{Динамика обучения самоигрой}\label{app:dynamics}

Правило выбора чекпойнта Q2 (разд.~\ref{sec:exp-questions}) отвечает на устойчивую картину переобучения, измеряемую в \emph{эпохах} по набору фрагментов, а не во внешних шагах: так как число батчей на эпоху равно $|\mathcal{D}|/B$, фиксированный бюджет шагов означает разное число эпох для разных корпусов. Узкие корпуса переобучаются -- статистика ($429$ документов) примерно к эпохе~$17$, линейная алгебра ($602$ документа) примерно к эпохам~$45$--$50$, -- тогда как более крупный STEM-корпус проходит лишь несколько эпох и к концу всё ещё улучшается. Поэтому выбор лучшего чекпойнта по точности на отложенной предметной выборке решающий для узких областей и почти не влияет на широкий корпус, а правило с фиксированным числом шагов было бы несправедливым по отношению к разным областям.

Кривые награды, доли верных ответов, доли корректных записей, лосса и времени шага для каждого запуска отслеживаются в MLflow.
